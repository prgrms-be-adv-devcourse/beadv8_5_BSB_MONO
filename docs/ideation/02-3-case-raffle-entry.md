# 판매 방식 사례 — 추첨(래플) 접수 후 당첨자만 결제

- 작성일: 2026-10-02
- 대상 제품: 크루 단체 대회 접수 + 크루원별 개별 결제 마켓플레이스 ([03 문제 정의](03-problem-definition.md) 기준)
- 조사 방법: 팀원이 공유한 검색 결과 캡처. 출처 표시는 뉴발란스 공식 홈페이지, 더트래커. 원문 페이지는 아직 직접 열어 보지 않았다.
- 표기: **[사실]** 캡처 내용 그대로 / **[추론]** 사실에서 끌어낸 해석 / **확인 필요** 아직 확인하지 않음

## 0. 핵심 결론

참가권을 **먼저 온 순서대로 파는 방식(선착순)만 있는 게 아니다.** 뉴발란스 대회는 응모를 받아 **무작위로 추첨하고, 당첨된 사람만 결제**하게 했다. 매장에서 러닝화를 사면 참가권을 주는 **패키지 선착순 판매**도 따로 열었다.

우리 서비스에는 다음 두 가지를 뜻한다.

1. 판매자가 대회마다 **판매 방식(선착순 / 추첨)을 고를 수 있어야** 한다.
2. 추첨은 접수 오픈 순간에 사람이 몰리지 않아서, **접속 대기열 없이도 공정하게 파는 다른 길**이 된다.

## 2. 선착순과 추첨 비교

| | 선착순 | 추첨 (래플) |
|---|---|---|
| 자리가 정해지는 기준 | 누가 먼저 눌렀나 | 무작위 |
| 몰리는 순간 | 접수 오픈 순간에 한꺼번에 | 응모 기간 동안 나뉘어 들어옴 |
| 필요한 장치 | 접속 대기열, 임시 확보, 짧은 결제 기한 | 중복 응모 막기, 추첨 기록, 당첨 후 결제 기한 |
| 결제 시점 | 자리를 잡은 직후 | 당첨 발표 후 (응모 때는 돈을 내지 않음) |
| 공정성 논란 | 속도·매크로 경쟁 | 추첨이 정말 무작위였는지 |

[02-1 러너블 분석](02-1-competitor-runable.md)에 나온 **KB 마라톤 카드 회원 대상 JTBC 서울마라톤 우선 응모(3,000명 추첨)**도 같은 방식이다. 큰 대회에서는 추첨 접수가 이미 쓰이고 있다 **[추론]**.

## 3. 이벤트 스토밍으로 쓰면 (추첨 흐름)

1. **판매 방식이 추첨으로 설정됨** (판매자: 응모 기간, 발표일, 당첨 인원, 결제 기한)
2. **응모가 시작됨** → **응모가 접수됨** (회원 1명당 1회)
   - 다른 경우: **중복 응모가 차단됨**
3. **응모가 마감됨**
4. **추첨이 실행됨** → **추첨 결과가 기록됨** (공정성 확인용)
5. **당첨자가 발표됨** → **당첨이 안내됨** / **미당첨이 안내됨**
6. **당첨자 결제 기한이 시작됨** → **결제 완료됨** → **참가 확정됨**
   - 다른 경우: **결제 기한이 지남** → **당첨이 취소됨** → **추가 당첨이 진행됨** (예비 당첨자에게 순서대로)
7. **추첨 접수가 종료됨**

## 4. 우리 서비스에 주는 질문 (핫스팟)

1. **크루 참가는 추첨에서 어떻게 하나?** 가장 중요한 질문이다.
   - 크루 단위로 한 번 응모하고, 당첨되면 크루 전체가 들어가는가?
   - 크루원이 각자 응모하면 "같이 나간다"가 보장되지 않는다.
   - 크루 단위 당첨은 개인 응모자보다 유리해서 공정성 문제가 생길 수 있다. 천안 마라톤 단체 접수 논란과 같은 지점이다 ([02](02-competitor-analysis.md) 참고).
2. 응모할 때 참가자 정보(이름·생년월일 등)까지 받을 것인가, 당첨 후에 받을 것인가
3. 당첨자 결제 기한은 며칠인가. 미결제 자리를 예비 당첨자에게 넘길 것인가
4. 한 사람이 여러 계정으로 응모하는 것을 어떻게 막을 것인가 (본인 확인)
5. 추첨이 무작위였다는 것을 어떻게 보여 줄 것인가 (추첨 기록 공개 범위)
6. 한 대회 안에서 추첨 몫과 선착순 몫을 나눠 팔 수 있게 할 것인가 (뉴발란스처럼 온라인 래플 + 매장 선착순)

## 5. 용어 제안 (10 유비쿼터스 언어에 추가 후보)

| 용어 | 뜻 |
|---|---|
| 판매 방식 | 대회 참가권을 선착순으로 팔지, 추첨으로 팔지 정한 것 |
| 응모 | 추첨에 참여하겠다고 신청하는 것. 돈은 내지 않는다 |
| 추첨 | 응모자 중 당첨자를 무작위로 뽑는 것 |
| 당첨 / 미당첨 | 추첨 결과. 당첨자만 결제할 수 있다 |
| 추가 당첨 | 당첨자가 결제하지 않아 남은 자리를 예비 당첨자에게 넘기는 것 |

"래플"은 같은 뜻이지만, 화면 문구와 코드에서는 "추첨"으로 통일하는 걸 추천한다.
