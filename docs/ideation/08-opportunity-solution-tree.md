# 기회-해결책 나무 (Opportunity Solution Tree)

- 작성일: 2026-10-05
- 상태: **초안 (팀 확인 전)**. 기회 점수는 인터뷰 전 **[가정]** 값이다. 인터뷰 후 매주 고친다.
- 근거: [04 가정 점검](04-assumptions.md), [05 여정 지도](05-customer-journey-map.md), [06 포지셔닝](06-positioning-moat.md), [07 북극성 지표](07-north-star-metrics.md)
- 사용한 방법: `opportunity-solution-tree` (Teresa Torres)
- 구조: **목표**(숫자 하나) → **기회**(고객이 겪는 문제, 기능이 아님) → **해결책**(기회마다 3개 이상) → **실험**(싸고 빠르게, 의견 말고 행동을 잰다)

## 0. 먼저 — 예전 '결정 필요 5개'는 정해졌다

1단계 추천 때 "정하지 않은 항목 5개를 이 나무로 정리하자"고 했다. 그런데 10/5 정책 점검본에서 5개 모두 정해졌다. 그래서 나무는 **남은 빈 곳**(04·05에서 찾은 것)을 다룬다.

| 예전 결정 필요 항목 (03 문서) | 10/5 정책에서 정해진 것 |
|---|---|
| 1. 미결제 인원 자동 취소 vs 크루장 마감 | 둘 다. 72시간 지나거나 크루장이 직접 마감, 미결제 자리는 자동 해제 [3-3-3, 3-4-1] |
| 2. 결제 전 자리 임시 확보 | 신청 인원만큼 크루 몫을 임시 확보 [3-3-2] |
| 3. 단체 할인 기준·부담 | 판매자가 켜고 부담, 정가 결제 후 사후 환급 [2-3] |
| 4. 대기자 구매 기한·알림 | 최종 프로젝트로 미룸 [정책 개요 4-1] |
| 5. 제작 굿즈 취소 불가, 정산 후 환불 | 제작 시작 후 취소 불가 + 결제 때 동의 [5-3-4], 다음 정산에서 차감·이월 [6-4] |

## 1. 목표

> **월간 크루 확정 참가자 수**를 늘린다 (07 북극성).
> 시범 목표 [가정]: 시범 대회 1개에서 크루 확정 300명, 크루 결제 전환율(I3) 80%.

## 2. 기회 찾기

여정 지도(05)의 감정이 낮은 지점에서 끌어냈다. 고객의 말투로 적는다.

| ID | 누가 | 기회 (고객의 말) | 중요도 | 만족도 | **기회 점수** | 07 지표 |
|---|---|---|---|---|---|---|
| O1 | 크루장 | "누가 안 냈는지는 보이는데, **재촉할 방법이 없어** 결국 카톡방에서 이름을 불러야 한다" | 0.9 | 0.2 | **0.72** | I3 |
| O5 | 판매자 | "크루 몫을 떼어 주고 할인 비용도 냈는데, **그 덕에 뭐가 나아졌는지 모르겠다**" | 0.8 | 0.1 | **0.72** | I1 |
| O6 | 판매자 | "대회 비용은 먼저 나가는데 **돈은 한 달 넘게 뒤에** 들어온다" | 0.9 | 0.3 | **0.63** | I1 |
| O2 | 크루원 | "처음 한 번 신청하는 데 **단계가 너무 많다**" | 0.8 | 0.3 | **0.56** | I4 |
| O4 | 크루장 | "몇 명이 갈지 모르는 채로 **10분 안에 신청 인원을** 정해야 한다" | 0.7 | 0.3 | 0.49 | I2, H1 |
| O7 | 개인 러너 | "크루 몫 때문에 **내 자리가 줄어드는** 것 같다" | 0.6 | 0.4 | 0.36 | H2 |
| O3 | 크루원 | "할인이 될지, **언제 돈이 들어올지** 모르겠다" | 0.5 | 0.4 | 0.30 | I3 |

- 기회 점수 = 중요도 × (1 − 만족도). 만족도는 "지금 정책·대체재로 얼마나 해결되나"
- **위 4개(O1·O5·O6·O2)에 집중한다.** O4·O7·O3은 이미 04·05 문서에 싼 해결책(신청 전 확인 단계, 크루 몫 공개, 할인 조건 표시)이 있어서 실험 없이 바로 반영한다.

## 3. 나무

```
목표: 월간 크루 확정 참가자 수
│
├─ O1 크루장: 재촉할 방법이 없다 (0.72)
│   ├─ S1-1 '결제 요청' 버튼 — 플랫폼이 미결제자에게 알림 ★
│   ├─ S1-2 마감 24시간·3시간 전 자동 알림 ★
│   ├─ S1-3 참가 링크·마이페이지에 남은 시간 카운트다운
│   ├─ S1-4 48시간째 미결제 자리 '해제 예정' 경고 (크루장·크루원 모두)
│   └─ ✕ S1-5 크루장이 대신 결제 — 문제 정의(대납 없애기)와 반대라 버림
│       └─ 실험 E1 (S1-1·S1-2)
│
├─ O5 판매자: 크루 몫의 효과를 모른다 (0.72)
│   ├─ S5-1 크루 효과 리포트 (크루 유입 인원, 크루 몫 소진율, 취소율 비교) ★
│   ├─ S5-2 크루 몫 실시간 현황 + 크루 몫 마감 후 이동 알림
│   ├─ S5-3 크루별 확정 명단 원클릭 내려받기 (지금 솔루션 형식으로)
│   └─ S5-4 대회 등록 때 크루 몫 비율 추천값 + "비슷한 대회는 크루가 X%"
│       └─ 실험 E2 (S5-1)
│
├─ O6 판매자: 돈이 늦게 들어온다 (0.63)
│   ├─ S6-1 대회 전 일부 선정산 (예: D-14에 확정 판매액의 일부)
│   ├─ S6-2 정산을 월 2회로
│   ├─ S6-3 이의 제기 기간 3일 → 1일
│   └─ S6-4 굿즈는 구매확정 다음 정산일이 아니라 주 단위로
│       └─ 실험 E3 (S6-1 vs S6-2)   ※ 1차 구현 밖. 실서비스 사업성 판단용
│
└─ O2 크루원: 첫 신청 단계가 많다 (0.56)
    ├─ S2-1 참가 링크 하나로 가입 → 크루 가입 → 합류 이어 붙이기 ★
    ├─ S2-2 결제 화면에서 부족분만 바로 충전 → 이어서 결제 ★
    ├─ S2-3 단계 표시(1/5) + "본인인증은 대회 보험 때문" 이유 안내
    └─ S2-4 소셜 로그인 프로필로 닉네임 미리 채움, 본인인증 정보로 참가자 정보 자동 입력
        └─ 실험 E4 (S2-1·S2-2)
```

★ = 실험 후 1차 구현 후보

### 해결책 비교 — 세 관점

| 해결책 | PM (가치) | 디자이너 (사용성) | 엔지니어 (구현) |
|---|---|---|---|
| S1-1 결제 요청 버튼 | 크루장이 카톡방으로 돌아가지 않게 하는 핵심 | 크루장이 누르는 버튼 하나, 크루원은 알림 하나 | 알림 서비스 필요. Kafka 이벤트 하나로 끝. 남용 막는 횟수 제한(하루 1회) |
| S1-2 자동 알림 | 크루장이 아무것도 안 해도 됨 | S1-1과 같이 쓰면 알림 피로 | 스케줄러 + 이벤트. 72시간 해제 로직과 같은 타이머를 씀 |
| S1-4 해제 예정 경고 | 마감 효과(손실 회피) | 경고 문구가 압박으로 느껴질 수 있음 (04 E3) | 타이머 하나 추가 |
| S5-1 크루 효과 리포트 | 해자 ①의 시동 장치 (06) | 숫자 3~4개면 충분 | 07 대시보드 집계를 판매자별로 자르면 된다 |
| S5-3 명단 원클릭 | 기존 솔루션 옆에서 쓰는 진입 전략 (06 Q3) | — | 엑셀 내보내기. 다운로드 사유 기록은 이미 정책 [3-1-4] |
| S6-1 선정산 | 판매자 설득에 가장 강함 | — | 돈이 먼저 나가서 환불 위험을 플랫폼이 떠안음. 규제 확인 필요 (04 B5·B6) |
| S2-1 링크 이어 붙이기 | 첫 결제 완료율(I4)에 바로 영향 | 이탈 지점 두 곳을 한 흐름으로 | 프론트 라우팅 문제. 백엔드는 '초대 토큰'만 넘기면 된다 |
| S2-2 부족분 충전 | 충전·결제 두 단계를 하나로 | 금액을 계산해 주는 게 핵심 | PG 충전 성공 → 결제 이어서 호출. 충전 성공·결제 실패 핫스팟과 같은 자리 (멱등성) |

## 4. 실험

| ID | 해결책 | 가설 | 방법 | 잴 것 | 성공 기준 [가정] | 비용 |
|---|---|---|---|---|---|---|
| E1 | S1-1·S1-2 | 플랫폼이 대신 알리면 크루장이 직접 재촉하지 않아도 72시간 안에 결제가 끝난다 | **컨시어지 테스트**: 실제 크루 1곳의 다음 단체 신청을 구글폼 + 계좌이체 그대로 하되, 미결제자에게 우리가 마감 24·3시간 전 문자를 대신 보낸다. 지난번 단체 신청 기록과 비교 | 마지막 입금까지 걸린 시간, 크루장이 직접 재촉한 횟수 | 입금 완료 시간 중앙값 30% 단축, 크루장 재촉 0~1회 | 크루 1곳, 1주 |
| E2 | S5-1 | 크루 효과를 숫자로 보면 판매자가 크루 몫을 연다 | 주최자 3곳에 **가상 리포트 목업**(크루 유입 인원·취소율 비교)을 보여 주고, "다음 대회에 크루 몫을 열어 보겠다"면 시범 대회 등록 사전 신청서(이름·대회명)를 받는다 | 사전 신청서 제출 수 (말이 아니라 행동) | 3곳 중 1곳 | 메일 + 통화 3건 |
| E3 | S6-1 vs S6-2 | 판매자는 선정산을 위해 수수료를 더 낼 의향이 있다 | 주최자 인터뷰에서 **세 가지 조건 카드**(지금 조건 / 월 2회 정산 / D-14 선정산 + 수수료 +2%p)를 고르게 한다 | 고른 카드와 이유 | 선정산 카드를 고른 곳이 절반 이상이면 실서비스 검토 | E2와 같은 통화 |
| E4 | S2-1·S2-2 | 링크를 이어 붙이고 부족분 충전을 붙이면 첫 신청을 도움 없이 끝낸다 | **클릭 프로토타입 A/B**: 지금 정책 흐름(A)과 이어 붙인 흐름(B)을 각각 5명에게. 카톡으로 링크를 받는 상황부터 시작 | 완료율, 걸린 시간, 막힌 단계 | B 완료율 4/5 이상, A보다 걸린 시간 30% 짧음 | 10명 × 15분 |

실험 순서: **E4 → E1 → E2·E3**. E4는 팀 안에서 와이어프레임만으로 바로 할 수 있고, E1은 팀원 지인 크루가 있으면 이번 주에 시작할 수 있다. E2·E3는 주최자 연락이 필요해 기획서 제출(10/7) 뒤로 둔다.

| S6-1·S6-2 | 넣지 않는다 | 실서비스 전 검토 (04 G6) |
