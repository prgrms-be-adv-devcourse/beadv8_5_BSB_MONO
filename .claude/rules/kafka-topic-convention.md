# Kafka 토픽 네이밍 컨벤션

출처: [Kafka Topic 네이밍 컨벤션](https://data-engineer-tech.tistory.com/36)

토픽을 만들거나(`NewTopic`/`TopicBuilder` 빈), `@KafkaListener`·`KafkaTemplate`에서 토픽 이름을 쓸 때 아래 규칙을 따릅니다.

## 규칙

**형식:** `<message-type>.<dataset-name>.<data-name>`

- 계층(구성 요소) 사이는 **마침표(`.`)로만** 구분합니다.
- 각 구성 요소는 **한 단어**로 짓습니다. 단어를 잇는 `-`, `_`는 쓰지 않습니다.
- 모두 소문자로 씁니다.

| 구성 요소 | 의미 | 예 |
|---|---|---|
| `message-type` | 데이터 흐름의 종류 | `logging`, `queuing`, `tracking`, `etl`/`db`, `streaming`, `push`, `user` |
| `dataset-name` | RDBMS의 데이터베이스 이름에 해당 | 데이터 묶음(도메인) 이름 |
| `data-name` | RDBMS의 테이블 이름에 해당 | 그 묶음 안의 개별 데이터 이름 |

```
queuing.member.joined
```

(예시 값은 형식을 보여 주기 위한 가정입니다. 출처 글에는 실제 토픽 이름 예시가 없습니다.)

## `.`과 `_`를 함께 쓰지 않는 이유

Kafka 토픽 이름에는 영문자, 숫자, `.`, `_`, `-`를 쓸 수 있지만, **`.`과 `_`는 충돌할 수 있어 함께 쓰면 안 됩니다.**
Kafka는 메트릭 이름을 만들 때 `.`을 `_`로 바꾸기 때문에 `a.b`와 `a_b`가 같은 이름으로 취급됩니다.
계층 구분에 `.`을 쓰므로 `_`는 쓰지 않습니다.

## 피해야 할 것

- **바뀔 수 있는 이름을 넣지 않습니다:** 팀 이름, 제품 이름처럼 시간이 지나면 바뀌는 이름
- **생산자/소비자 이름을 넣지 않습니다:** 어떤 서비스가 보내고 받는지는 바뀌므로, 토픽 이름은 데이터 자체를 나타냅니다
- **토픽 자동 생성에 기대지 않습니다:** 글에서는 `auto.create.topics.enable=false`로 꺼서 규칙에 맞지 않는 토픽이
  생기지 않게 하라고 권합니다

## 적용 (프로젝트 보완 사항)

출처 글에 없는 내용으로, 이 프로젝트에서 위 규칙을 적용하는 방법입니다.

- **이 프로젝트는 위 "토픽 자동 생성에 기대지 않습니다"를 따르지 않고, 토픽 자동 생성을 허용합니다.**
  로컬 Redpanda(`compose.yml`)는 `dev-container` 모드라 자동 생성이 켜져 있으므로, 토픽은 `NewTopic` 빈 없이
  처음 메시지를 보내거나 구독할 때 만들어집니다. 파티션을 2개 이상으로 늘려야 하는 토픽만 `NewTopic`/`TopicBuilder` 빈으로 선언합니다.
- 토픽 이름 문자열은 상수로 한곳에 모아, 생산자와 소비자가 같은 상수를 참조합니다. 오타로 다른 토픽이 생기는 것을 막습니다.
