# Redis 키 네이밍 컨벤션

출처: [JSCODE - Redis Key 네이밍 컨벤션](https://www.jscode.kr/blog/redis-key-naming-convention)

Redis에 값을 저장하는 코드(`RedisTemplate`, `@Cacheable` 등)를 작성할 때 키 이름은 아래 규칙을 따릅니다.

## 규칙

**콜론(`:`)으로 구분해 계층적으로 의미를 나타냅니다.** 키는 `{엔티티}:{ID}:{속성}` 순서로 구성합니다.

```
users:100:profile        # users(대상) → 100(ID) → profile(속성)
products:123:details     # products(대상) → 123(ID) → details(속성)
```

| 위치 | 의미 | 예 |
|---|---|---|
| 1번째 | 어떤 대상(엔티티 종류)의 데이터인지 | `users`, `products` |
| 2번째 | 그 대상 중 어떤 것인지 (식별자) | `100`, `123` |
| 3번째 | 그 대상의 어떤 정보인지 (속성) | `profile`, `details` |

## 이렇게 하는 이유

1. **가독성:** 키 이름만 보고 어떤 데이터인지 바로 알 수 있습니다.
2. **일관성:** 모든 코드가 같은 방식으로 키를 만들어 유지보수가 쉬워집니다.
3. **검색 용이성:** `users:100:*`처럼 패턴으로 관련 키를 한꺼번에 찾을 수 있습니다.
4. **충돌 방지:** 계층으로 나뉘어 있어 서로 다른 데이터의 키가 겹치지 않습니다.
   서비스를 나눈 뒤에도 같은 Redis를 함께 쓸 수 있으므로 특히 중요합니다.

## 적용

- 위 형식은 반드시 지켜야 하는 고정 규칙이 아니라 업계에서 흔히 쓰는 방식입니다. 데이터 성격에 따라
  계층을 줄이거나 늘려 응용할 수 있습니다. 단, **콜론 구분과 "큰 범위 → 작은 범위" 순서**는 유지합니다.
- 키 문자열을 코드 곳곳에서 직접 이어 붙이지 않고, 키를 만드는 메서드나 상수를 한곳에 모아 같은 형식을 재사용합니다.
