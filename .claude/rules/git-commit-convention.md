[Conventional Commits 1.0.0](https://www.conventionalcommits.org/ko/v1.0.0/)을 따릅니다. 설명과 본문은 한국어로, 타입과 스코프는 영어로 작성합니다.

## 형식

```
<타입>[(스코프)][!]: <설명>

[본문]

[꼬리말]
```

- 타입 뒤에 콜론과 공백(`: `)을 붙이고 설명을 씁니다.
- 설명은 한 줄로 짧게, 마침표 없이 씁니다.
- 본문과 꼬리말은 선택이며, 앞에 빈 줄 하나를 둡니다. 본문에는 무엇을, 왜 바꿨는지 씁니다.

## 타입

| 타입 | 용도 |
|---|---|
| `feat` | 새 기능 추가 |
| `fix` | 버그 수정 |
| `refactor` | 기능 변화 없는 코드 구조 개선 |
| `perf` | 성능 개선 |
| `test` | 테스트 추가, 수정 |
| `docs` | 문서 수정 |
| `style` | 포매팅만 바꿈. 화면 모양이 바뀌면 쓰지 않고 `fix`(시안과 다른 것을 고침)나 `feat`(새 요소)을 쓴다 |
| `build` | 빌드 설정, 의존성 변경 (`build.gradle.kts` 등) |
| `ci` | CI 설정 변경 |
| `chore` | 그 밖의 잡무 (설정 파일 정리 등) |
| `revert` | 이전 커밋 되돌리기 |

## 스코프

변경된 영역을 괄호 안에 아래 18개 중에서 적습니다. 선택이지만 영역이 분명하면 붙입니다. 목록 밖 이름은 commitlint가 경고합니다(일주일 뒤 실패로 올립니다).
영역은 백엔드 서비스 이름을 기준으로 하고, 판매자센터·관리자 화면도 다루는 도메인의 영역을 씁니다. 프론트·백엔드 구분은 영역이 아니라 위치 라벨로 합니다.

| 영역 | 범위 |
|---|---|
| `member` | 회원, 로그인·토큰, 크루 |
| `product` | 대회, 종목, 상품, 키트 |
| `order` | 주문, 결제, 파티, 참가권 |
| `queue` | 대기열 |
| `cash` | 예치금, 충전, 환급 |
| `payout` | 정산 |
| `board` | 커뮤니티 |
| `inquiry` | 문의 |
| `notification` | 알림 |
| `file` | 파일 |
| `ai` | AI 기능 |
| `gateway` | 게이트웨이 |
| `common` | 백엔드 공용 모듈 |
| `design` | 프론트 공용 부품, 디자인 토큰 |
| `infra` | 서버, k8s, nginx, 모니터링 |
| `ci` | GitHub Actions, 검사 스크립트 |
| `e2e` | E2E 테스트 |
| `loadtest` | 부하 테스트 |

- 예: `feat(member): 회원 가입 API 추가`, `fix(order): 결제 취소 시 재고 복구`

## 브랜치 이름

형식: `<종류>/<이슈 번호>-<영어 설명>`. 종류는 커밋 타입과 같고, 이슈 번호는 GitHub 이슈 번호입니다. 예: `fix/812-queue-reentry`

- 이슈 없이 자동으로 여는 PR은 `<종류>/auto-<영어 설명>`을 씁니다. 예: `chore/auto-retro-2026-11-30`
- 영어 소문자·숫자·`-`만 씁니다. `claude/…` 같은 기본 이름은 PR 검사(`pr-branch`)를 통과하지 못합니다.
- `dev`→`main` 동기화 PR은 검사하지 않습니다.

## 호환성을 깨는 변경 (BREAKING CHANGE)

API 응답 형식 변경처럼 기존 사용처가 깨지는 변경은 반드시 표시합니다. 둘 중 하나 이상을 사용합니다.

- 타입(또는 스코프) 바로 뒤에 `!` 표시: `feat(member)!: 회원 응답 필드명 변경`
- 꼬리말에 `BREAKING CHANGE: <설명>` 작성 (`BREAKING CHANGE`는 반드시 대문자)

## 꼬리말

`토큰: 값` 형식이며, 토큰의 공백은 `-`로 대체합니다 (`BREAKING CHANGE`만 예외).

- 예: `Refs: #123`, `Reviewed-by: 홍길동`, `Co-Authored-By: ...`

## 예시

```
feat(member): 회원 가입 API 추가

이메일 중복 검사 후 회원을 저장한다.
비밀번호는 BCrypt로 암호화한다.

Refs: #12
```

```
build: Checkstyle 플러그인 추가

캠퍼스 핵데이 Java 컨벤션 규칙을 원격 URL로 참조한다.
```

```
refactor(order)!: 주문 상태 enum 값 변경

BREAKING CHANGE: ORDERED 상태가 PLACED로 바뀌어 기존 클라이언트 수정이 필요하다.
```

## 커밋 단위

- 하나의 커밋에는 하나의 목적만 담습니다. 기능 추가와 리팩터링이 섞이면 커밋을 나눕니다.
- 여러 타입에 걸친 변경이라면 가능한 한 커밋을 분리합니다.
