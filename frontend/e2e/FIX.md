# 점심 E2E 실패 고치기

이 문서는 팀원 노트북의 Claude가 읽는 규칙이에요.
`scripts/e2e-lunch.sh run <이름>`이 끝났을 때 실패한 시나리오가 있으면 이 규칙대로 고치고 다시 돌려요.
`<이름>`은 jihoon, dawit, youngho, sohee, hobin 중 하나예요.

점심시간에는 팀원이 자리를 비워서 `scripts/e2e-lunch.sh auto <이름>`이 Claude를 사람 없이 실행해요.
그래서 질문하지 않아요. 판단이 애매하면 실제 버그로 기록하고 다음 실패로 넘어가요.
auto 모드에서는 테스트 코드 수정과 `-fix.md` 기록만 해요. 다시 돌리기와 `-fix.patch` 만들기는 스크립트가 해요.

## 1. 실패 목록 보기

`frontend/e2e-<이름>.json`에서 결과가 실패인 테스트를 모두 찾아요.
테스트마다 오류 문구, 실패한 코드 줄, 스크린샷 위치(`frontend/test-results/` 안)를 확인해요.
오류 문구에 API 응답이 들어 있으면 상태 코드와 `code` 값도 함께 확인해요.

## 2. 실패를 세 종류로 나누기

실패 하나마다 아래 셋 중 하나로 정해요.

| 종류             | 이런 경우예요                                                                                                                         | 하는 일                                                      |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 환경 문제        | 앱이 꺼져 있어요. 포트가 겹쳐요. 앱이 늦게 떠서 첫 요청이 시간 초과됐어요.                                                            | 환경을 고치고 다시 돌려요.                                   |
| 테스트 코드 문제 | 버튼 이름이나 화면 문구가 테스트에 적힌 것과 달라요. 테스트가 기다리는 위치가 틀렸어요. 테스트가 보낸 요청 본문에 필수 칸이 빠졌어요. | `frontend/e2e/lunch/` 안의 테스트 코드를 고치고 다시 돌려요. |
| 실제 버그        | API가 500을 돌려줘요. 금액이나 잔액이 틀려요. 한 서비스의 변경이 다른 서비스에 반영되지 않아요. 화면이 오류 문구를 보여 줘요.         | 고치지 않아요. 증거만 남겨요.                                |

헷갈리면 실제 버그로 정해요.
테스트를 잘못 고쳐서 버그가 가려지는 것보다, 버그로 남겨서 지훈 님이 한 번 더 확인하는 쪽이 안전하기 때문이에요.

## 3. 하면 안 되는 일

- 프론트(`frontend/src/`)와 백엔드(`backend/`)의 앱 코드는 고치지 않아요. 점심시간에 앱 코드를 고치면 무엇이 깨졌는지 기록이 남지 않아요.
- 테스트의 확인 항목(`expect`)을 지우지 않아요. 확인 항목을 지우면 실제 버그가 가려져요.
- 기다리는 시간을 테스트에 적힌 값보다 늘리지 않아요. 이 값은 설계에서 정한 최대 시간이라서, 넘기면 실패로 보는 게 맞아요.
- 재시도 코드를 넣지 않아요. 재시도를 넣으면 가끔 빠지는 이벤트를 찾지 못해요.
- 커밋과 푸시를 하지 않아요. 고친 테스트 코드는 지훈 님이 모아서 PR 하나로 반영해요.

## 4. 환경 고치기

`run`이 실패로 끝나면 앱과 프론트를 켜 둔 채 끝나요. 그래서 보통은 바로 다시 돌릴 수 있어요.
앱이 켜져 있는지는 아래 명령으로 확인해요. 응답 코드가 200이나 503이면 켜져 있는 거예요.

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8000/actuator/health
```

앱이 꺼졌거나 포트가 겹칠 때만 아래 명령으로 앱을 다시 띄워요.

```bash
cd frontend
./scripts/e2e-lunch.sh pretest <이름>
```

pretest는 로컬 DB를 지우고 새로 만들어요. 그래서 앞에서 만든 테스트 데이터는 사라져요.
pretest가 실패하면 화면에 나온 원인 줄을 `frontend/e2e-<이름>-fix.md`에 그대로 적고 멈춰요.

## 5. 실패한 시나리오만 다시 돌리기

실패한 시나리오 번호를 `|`로 이어서 넘겨요.
아래 예시는 다윗 님의 25번과 65번만 다시 돌려요.

```bash
cd frontend
./scripts/e2e-lunch.sh run dawit "25|65"
```

- 다시 돌린 뒤에도 실패가 남으면 앱은 계속 켜져 있어요. 모두 통과하면 스크립트가 앱과 컨테이너를 정리해요.
- 다시 돌리기는 최대 2번이에요.
- 13:50이 되면 고치던 일을 멈추고 지금까지의 결과를 남겨요.
- 다시 돌린 결과는 같은 `frontend/e2e-<이름>.json`에 덮어써요. 덮어쓰기 전에 처음 결과의 실패 목록을 `-fix.md`에 먼저 적어 둬요.

다 끝났는데 앱이 켜져 있으면 아래 명령으로 정리해요.

```bash
cd frontend
./scripts/e2e-lunch.sh stop
```

## 6. 남길 파일

두 파일을 `frontend/` 폴더에 만들어요. 두 파일은 git에 잡히지 않게 되어 있어요.

`frontend/e2e-<이름>-fix.patch`는 고친 테스트 코드예요. 아래 명령으로 만들어요.

```bash
git diff -- frontend/e2e > frontend/e2e-<이름>-fix.patch
```

`frontend/e2e-<이름>-fix.md`는 실패 기록이에요. 실패한 시나리오마다 아래 네 가지를 적어요.

- 시나리오 번호와 이름
- 나눈 종류 (환경 문제, 테스트 코드 문제, 실제 버그)
- 한 일: 환경을 어떻게 고쳤는지, 테스트 코드의 어느 줄을 무엇으로 바꿨는지
- 실제 버그라면 증거: 요청 주소와 본문, 응답 상태 코드와 본문, 스크린샷 파일 위치, 다시 돌려도 같은지

마지막에 다시 돌린 횟수와 최종 결과(통과 수, 실패 수)를 한 줄로 적어요.
두 파일은 `e2e-<이름>.json`, 실패 스크린샷과 함께 슬랙 스레드에 올려요.
