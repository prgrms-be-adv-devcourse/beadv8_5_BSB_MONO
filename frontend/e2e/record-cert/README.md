# 기록증 심사 E2E

기록증 제출부터 심사까지(BUK-274~277)를 실제 백엔드와 브라우저로 확인해요.
가짜 응답 모드가 아니라, 띄워 둔 서버(게이트웨이 · member · file · product · order · ai-service · 프론트)를 그대로 써요.

## 시나리오

| #   | 파일                  | 흐름                                                                                                |
| --- | --------------------- | --------------------------------------------------------------------------------------------------- |
| 1   | `happy-path.spec.ts`  | 화면 업로드 → 브라우저 OCR → 제출 → 서버 확인 → 자동 승인(심사 필요면 판매자 승인)                  |
| 2   | `review-flow.spec.ts` | 제출 거절: 없는 · 남의 참가권, 없는 · 남의 사진, 규칙 없는 종목, 다시 내기, 이미 낸 사진 다시 쓰기  |
| 3   | `review-flow.spec.ts` | 서버 확인 실패: 열리지 않는 사진은 모든 칸 읽지 못함 → 심사 필요 (멀쩡한 사진은 자동 승인으로 대조) |
| 4   | `review-flow.spec.ts` | 판매자 심사: 목록 · 심사 대기 수 · 상세의 사진 보기 주소 · 승인 · 승인 불가(사유 · 메모) · 권한     |
| 5   | `review-flow.spec.ts` | 환불로 닫기: 참가권을 취소하면 제출이 취소됨, 그 뒤 심사 · 다시 내기가 막힘                         |
| 6   | `briefing.spec.ts`    | AI 브리핑(CRU-16): 심사 대기 0건이면 안 나오고, 1건이면 문장 · 할 일이 나오고, 승인하면 사라짐      |

- 1은 브라우저로, 2~6은 API로 확인해요. 판매자 심사 화면이 아직 없어요.
- 2~5는 대회 두 개(규칙 있음 · 없음)를 한 번만 만들어 함께 써요. 그래서 순서대로(serial) 돌아요.
- `support.ts`의 `CERT_BOXES`는 시나리오 1에서 브라우저 OCR이 실제로 찾은 칸 위치예요. 사진을 바꾸면 같이 바꿔요.
- 3의 깨진 사진은 그림 데이터를 0으로 바꾼 PNG예요. 뒤만 자른 파일은 서버가 열어 버려서 실패 갈래를 타지 않아요.
- 6은 남아 있는 심사 필요 제출을 먼저 모두 승인해 0건에서 시작해요. AI 질문(「심사 대기 몇 건?」)은 모델을 못 쓰는 환경(503)이면 건너뛰어요.
- 아직 없는 것: 다른 판매자의 대회를 볼 때 403(시드 판매자가 한 명), 미연결 파일 정리 배치.

## 실행

```bash
cd frontend
pnpm exec playwright install chromium   # 처음 한 번
E2E_BASE_URL=http://localhost:3177 pnpm test:record-cert
```

- 프론트는 `API_MOCKING=off`로 띄워 두고 주소를 `E2E_BASE_URL`로 넘겨요. 게이트웨이 주소는 `E2E_API_URL`(기본 `http://localhost:8000`)이에요.
- 로그인 · 구매 · DB 도우미는 점심 E2E의 `../lunch/support.ts`를 같이 써요. DB는 `bukang-db` 컨테이너에 직접 넣어요.
- 사진은 합성 기록증(`fixtures/synthetic-s-006.png`)만 써요. 실제 기록증은 넣지 않아요.

## 알아 둘 것

- 판매 상태 배치(5분 주기)를 두 번 기다려서 전체가 7~10분쯤 걸려요.
- OCR 읽기 제한 10초는 「이 부분 읽기」를 누른 때부터 세요. 느린 PC는 모델 준비에 8~10초가 걸려서, 테스트가 준비를 기다린 뒤 눌러요.
- file-service의 dev 전용 CORS는 `localhost:8085`만 허용해요. 프론트가 넘긴 Origin이 403으로 막혀서, 파일 API 요청만 테스트가 대신 보내요. prod에는 이 설정이 없어요.
- 막 띄운 서버는 첫 요청이 느려 504가 날 수 있어요. 업로드 확인이 실패하면 테스트가 「제출하기」를 다시 눌러요(최대 3번).
