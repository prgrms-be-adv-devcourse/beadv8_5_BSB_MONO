# 시나리오 A 부하 테스트 결과: 10% 2차 (2026-11-15)

1차(`2026-11-15-10pct.md`)에서 남긴 숙제 두 가지를 확인하려고 같은 10%를 한 번 더 돌렸어요.
- 1차의 멈춤(버려진 반복 218건)이 다시 나는지, 그때 맥 상태는 어떤지
- 결제 안쪽(예치금·상품 호출)에서 시간이 어디에 쓰이는지 (주문 서비스 내부 호출을 추적에 잡히게 고친 뒤)

## 한 줄 결론

응답 시간·에러율 기준은 통과했고 결제 2,400건이 모두 성공했어요. 멈춤은 두 번 다시 나서 버려진 반복이 1,148건이에요.
두 번 모두 모든 서비스가 동시에 느려졌고 그 순간 맥이 메모리를 한꺼번에 정리한 흔적이 있어, 서비스 코드보다 맥 한 대에 모두 띄운 환경 쪽으로 봐요.
결제(평균 38ms)는 예치금 호출 32%, 주문 안쪽 29%, 자리 판매 21%, 키트 옵션 조회 18%로 나뉘어요.

## 1차와 달라진 조건

나머지 조건(컴퓨터, Docker 6GB, 서비스 6개, dev + `run-env.sh`의 로그 info·샘플링 0.1, 주문의 http 모드, Ollama 끔, 부하 숫자, 워밍업 2분)은 1차와 같아요.
코드는 커밋 `7186b91d` + 커밋하지 않은 주문 서비스 4개 파일·`scenario-a.js` 한 줄이에요.
