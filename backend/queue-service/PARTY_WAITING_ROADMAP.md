# 파티 대기열 로드맵

작성: 2026-11-05 · 담당: 김호빈 (대기열 서비스)

크루 내 파티가 대회에 참가할 때 거치는 대기열을 만든다. 개인 대기열(등록 → 순번 조회 → 승격 → 입장 확인)과 같은 방식으로 움직이고, 줄과 API만 따로 둔다.

## 흐름

1. 파티 예매 가능 기간에 파티장이 상품 페이지에서 [대회 참가 신청]을 누른다.
   - 프론트가 먼저 주문 서비스의 파티장 확인 API를 부른다. 파티장이 아니면 Alert로 막는다.
2. 프론트가 파티 대기열 등록 API를 부른다(대회 ID, 파티 종목 ID). 파티장은 파티 대기열에서 기다린다.
3. 대기 화면이 순번 조회를 몇 초마다 부른다. `canEnter = true`가 되면 [대회 참가] 화면으로 넘어간다.
4. 파티장이 [대회 참가]를 누르면 주문 서비스가 파티용 입장 확인 내부 API로 입장 중인지 본다.
   그다음 파티 인원만큼 크루 몫에서 자리를 확보한다. 남은 크루 몫이 파티 인원보다 적으면 확보에 실패한다.
   (4는 주문·상품 서비스 작업이다. 이 문서의 범위는 2~3과 4의 입장 확인 API까지다.)

## 정한 것

| 항목 | 결정 | 이유 |
|---|---|---|
| 파티 종목 | 파티는 종목 하나다 (11/05 팀 결정, PR #314 `order_party.race_course_id`) | 파티원별 종목은 고도화로 미룸 |
| 줄 세울 값 | 파티장 회원 ID | 한 사람은 한 대회에 살아 있는 신청을 하나만 가질 수 있어(`uk_participation_active`), 대회 하나에 파티장 한 명이 이끄는 파티도 하나다. 순번 조회를 개인처럼 로그인 헤더로 할 수 있다 |
| 파티 ID | 대기열은 받지 않는다 | 주문 서비스가 [대회 참가] 때 대회 ID와 파티장 ID로 파티를 찾는다 |
| 파티장 확인 | 주문 서비스와 프론트가 한다. 대기열은 확인하지 않는다 | 대기열에는 파티 정보가 없다. 파티장이 아닌 사람이 줄을 서도 [대회 참가]에서 서버가 다시 막는다 |
| API | 파티용 등록·순번 조회·입장 확인을 개인과 따로 둔다 (다윗님과 합의) | 주문 서비스가 어느 API로 확인했는지로 파티 입장인지 개인 입장인지 알 수 있다 |
| 기간 | 크루 예매 기간과 개인 예매 기간은 겹치지 않는다 | 같은 사람이 같은 종목에서 두 줄에 동시에 입장할 일이 없다 |

## 다른 담당자에게 받을 것

- 주문(다윗님): 이 대회 내 파티 상태 API `GET /api/v1/order/parties/me/race-status?raceId=` (BUK-91, PR #333 머지).
  파티가 없어도 200에 `role=NONE`을 준다. 파티장이면 `role=LEADER`와 파티 번호·종목(`raceCourseId`)·상태를 주고,
  `canApply=true`(모집 중, 접수 중인 대회, 인원이 최소~최대)일 때만 파티 대기열에 넣는다.
  프론트는 여기서 받은 종목으로 파티 대기열에 등록한다.

파티 입장 여부는 대기열이 제공한다. 개인 입장 확인 API처럼 파티용 입장 확인 내부 API(작업 4)가 입장 중인지와 입장 끝 시각을 답한다. 주문 서비스는 이 API를 부르기만 한다.

## 작업

### 0. 선행: 대회 변경 메시지에 크루 일정 넣기 (상품 서비스·common)

- `common`의 `RaceChangedEvent`에 `crewSaleStartAt`, `crewSaleEndAt`을 더한다(빈 값 허용 = 크루 모집 없는 대회).
- 상품 서비스가 대회를 저장하거나 바꿀 때 두 값을 함께 싣는다.
- 받는 쪽이 모르는 칸을 무시하는지 확인한다. 배포 순서가 바뀌어도 기존 소비자가 깨지면 안 된다.

### 1. 크루 일정 복제하기

- `QueueRace`에 `crewSaleStartAt`, `crewSaleEndAt`을 더한다(빈 값 허용).
- `QueueKafkaConsumer` → `QueueFacade.syncRace` → `QueueSyncRaceUseCase`가 두 값을 저장하게 한다.
- 대기열 서비스는 `ddl-auto: update`라 칸은 자동으로 생긴다. 이미 있는 행은 다음 대회 변경 메시지가 올 때까지 빈 값이다.
  → 이미 등록된 대회는 상품에서 다시 저장하거나 메시지를 다시 보내야 파티 대기열이 열린다.

### 2. 파티 입장 가능 판정

- `QueueRace.isPartyEnterable(now)`를 더한다.
  - 크루 일정이 있다
  - 크루 예매 시작 ≤ 지금 < 크루 예매 마감
  - 지금 < 접수 마감
  - 판매 상태: 판매 중. 크루 예매 시작일 0시에는 상태 배치가 판매 중으로 바꾸기까지 최대 5분 걸린다.
    상품의 자리 확보처럼 판매 예정도 허용할지 구현 때 정한다.
- 기존 `isEnterable`(개인)은 그대로 둔다.

### 3. 파티 줄 (Redis)

- 키 (`.claude/rules/redis-key-convention.md`)
  - 기다리는 줄: `race:{raceId}:racecourse:{raceCourseId}:party:waiting` (ZSet, score = 등록 시각)
  - 입장한 줄: `race:{raceId}:racecourse:{raceCourseId}:party:active` (ZSet, score = 입장 끝 시각)
  - 승격할 파티 줄 목록: `queue:party:waiting` (Set, 값 = `{raceId}:{raceCourseId}`)
- 개인용 `queue:waiting`과 목록을 나눠, 개인 승격과 파티 승격이 서로 섞이지 않게 한다.
- 등록·승격 Lua 스크립트(`queue-register.lua`, `queue-promote.lua`)는 키만 바꿔 그대로 쓴다.
- `QueueRedisRepository`의 키 메서드에 파티용을 더한다. 키 문자열은 이 클래스 한곳에서만 만든다.

### 4. API

| 용도 | 주소 (안) | 받는 값 | 답 |
|---|---|---|---|
| 파티 대기열 등록 | `POST /api/v1/queue/parties` | 대회 ID, 종목 ID, 로그인 회원(파티장) | 순번, 앞 인원, 전체 인원 |
| 파티 순번 조회 | `GET /api/v1/queue/parties/races/{raceId}/racecourses/{raceCourseId}` | 로그인 회원 | 기다리는 중이면 순번, 입장했으면 `canEnter = true` |
| 파티 입장 확인 (내부) | `GET /internal/v1/queue/parties/races/{raceId}/racecourses/{raceCourseId}?memberId=` | 파티장 회원 ID | 입장 중인지, 입장 끝 시각 |

- 오류는 개인 대기열과 같은 형식(RsData)이다.
  - 403: 이 대회의 종목이 아님, 크루 예매 기간이 아님
  - 404: 없는 대회·종목
  - 409: 이미 입장함
  - 503: Redis 연결 실패 (대기열 없이 통과시키지 않는다)
- 같은 파티장이 여러 기기에서 등록하면 처음 순번을 유지한다.
- Swagger: 응답 예시 상수(`QueueApiExamples` 등)를 더한다(`/swagger-annotate`).
- 게이트웨이: `/api/v1/queue/**` 라우팅은 이미 있다. 로그인이 필요한 주소라 공개 주소에는 넣지 않는다.
- 등록 API 설명에 "등록 전에 주문 서비스의 파티장 확인 API로 확인"을 적는다.

### 5. 승격

- `QueuePromotionScheduler`가 `queue:party:waiting` 목록도 돌며 승격한다.
- 설정값을 개인용과 따로 둔다 (`QueueProperties`, `application.yaml`).
  - `queue.party.schedule.size`: 한 번에 올리는 파티 수. 파티 하나가 자리를 여러 석 잡으므로 개인(20)보다 작게 시작한다.
  - `queue.party.active.time`: 파티장 입장 시간. 시작값은 개인과 같은 10분.
- 끝 시각이 지난 입장은 개인과 같이 승격할 때 지운다. 두 줄이 모두 비면 목록에서 뺀다.

### 6. 테스트

- `QueueRaceTest`: 크루 기간 경계 (시작 시각 = 입장 가능, 마감 시각 = 불가, 크루 일정이 없는 대회 = 불가, 접수 마감 뒤 = 불가)
- 동기화: 크루 일정이 담긴 대회 메시지를 받으면 복제본에 저장되고, 옛 메시지는 무시된다.
- Redis 통합(`QueueIntegrationTest` 기반, Testcontainers)
  - 파티 등록·승격이 개인 줄에 영향을 주지 않는다
  - 같은 파티장이 다시 등록해도 처음 순번이 유지된다
  - 입장 끝 시각이 지나면 순번 조회와 입장 확인 모두 입장 중이 아니다
- 동시 등록: 같은 파티장이 동시에 여러 번 등록해도 줄에는 한 자리만 생긴다.
- 컨트롤러: 오류 응답 코드별 (403·404·409·503), 내부 입장 확인 응답 형식

## 범위 밖

- 파티장 확인, 파티 상태 확인, 파티 인원 확인 (주문 서비스)
- 크루 몫 자리 확보·판매·해제·1시간 배치 (상품 서비스, 따로 로드맵)
- 파티원별 종목 선택 (고도화, 종목 ID 순서로 잠가 교착을 막아야 함)
- 프론트 파티 대기 화면
